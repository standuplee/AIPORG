# 월간 종합 보고서 설계 (Phase 4)

상태: 승인 대기. 기준: [V1 구현 계획서](../plans/2026-11-17-aiporg-v1-implementation.md), [7월 월간 보고서 요구사항](../../aiporg2/monthly-keyword-report-requirements.md), 루트 `AGENTS.md`.

## 1. 의도와 이유

사용자가 지정한 이슈 4~5개를 새 엔진(이슈 조사·논점·반응)이 조사하고, 그 결과로 **7월 보고서와 같은 구성(요약·개요·이슈별 장·채널·TOP20·감성·시사점·출처)의 월간 보고서**를 만든다.
보고서의 모든 숫자가 하나의 문서 모음에서 나오도록, 새 엔진이 모은 문서를 2.0의 문서·Evidence·Analytics 흐름에 적재한다(결정: 방식 B). 감성 비율은 Qwen이 문서별로 분류하고 사람이 표본을 검수한다(결정).

## 2. 목표 / 비목표 / 반(反)목표

**목표**
- 보고서의 건수·비율·순위는 모두 2.0 Analytics가 계산한 값만 쓴다(단일 숫자 원칙).
- 이슈 장의 사실·논점·승인된 반응은 새 엔진의 검토 완료 결과를 쓴다.
- 감성 비율은 분모·미분류율·검수 표본 결과를 함께 표시한다.
- 기존 2.0 UI·승인·HWPX 흐름을 유지하고 그 위에 얹는다.

**비목표(이번 설계 범위 밖)**: 외부 여론조사 블록, X·인스타그램 수집, 정보 공백 반복 조사 루프, PostgreSQL 전환, HWPX 실기(한컴) 레이아웃 확정, 자동 이슈 발굴.

**반목표(기술적으로 동작해도 실패인 것)**
- 감성 비율을 도민 지지율·여론 방향으로 표현한다.
- 근거 없는 건수·비율·증감률을 채운다(비교 기간 자료가 없으면 "산출 불가").
- 이슈 장 숫자와 요약 숫자가 서로 다른 수집분에서 나와 어긋난다.

## 3. 제약

- AGENTS.md: 새 schema 임의 추가 금지, 기존 모델명 변경 금지, DB write는 Repository만, Collector에 LLM 호출 금지, Analyzer에 웹 요청 금지, Writer는 새 Fact 금지, 근거 없는 숫자 금지, 모듈 변경마다 단위 테스트, 통합 테스트 실패 시 다음 기능 금지.
- 2.0 문서는 게시일이 필수(`RawDocument.published_at`). 프로젝트 워크플로 상태는 각 상태를 한 번만 거치며 재수집은 새 프로젝트로 한다.
- 2.0 채널은 news/blog/community/social/video 5종. 값 추가는 승인 사항이다.
- 새 엔진은 현재 사실 쪽 검색 결과(뉴스·웹)를 문서로 보존하지 않고, 블로그·카페 글은 스니펫만 가진다.

## 4. 접근 방법 (선택 이력)

| 안 | 내용 | 결과 |
|---|---|---|
| A. 조립기가 두 산출물을 읽기만 | 코드 변경 최소, 수집 두 번·수치 출처 둘로 분리 | 비선택(숫자 불일치 위험) |
| **B. 새 엔진 수집분을 2.0에 적재** | 한 코퍼스에서 모든 수치 | **선택(사용자)** |
| C. 새 엔진에 감성·TOP20·채널 비중 추가 | 2.0 분석과 중복 | 비선택 |

감성 분류 방식: ①기존 사전 분류기 / **②Qwen 문서별 분류 + 표본 검수** / ③병행 → **②선택(사용자)**.

## 5. 설계

### 5.1 흐름

```text
새 엔진 이슈 조사(검토 완료) ──▶ 코퍼스 저장(사실·반응 검색분 전체, 본문 확보 여부 포함)
        │
        ▼
재생 수집기(BaseCollector 규격) ──▶ 2.0 MultiQueryCollectionToEvidence 워크플로
   · 질의 문자열 = 사용자 이슈명(이슈 1개 = 2.0 이슈 1개)
   · 게시일 없는 글은 적재하지 않고 "보류 N건"으로 기록
        │
        ▼
문서별 감성 분류(Qwen, 분석 계층) ─▶ 근거 구절을 코드가 확인 ─▶ 표본 검수
        │
        ▼
2.0 Analytics(채널·키워드·감성·이슈 언급량·비교) ─▶ 보고서 조립(7월 구성) ─▶ 승인 ─▶ HWPX/DOCX/MD
        ▲
이슈 장 = 새 엔진 IssueReport(사실·논점·승인 반응, 서술은 유지·숫자는 2.0 값으로 교체)
```

### 5.2 구성요소와 작업 순서 (독립 프로젝트 5개)

1. **코퍼스 저장과 재생 적재.** 새 엔진이 검색한 모든 결과(사실·반응)와 확보한 본문을 이슈별 JSON에 저장한다. 재생 수집기가 이를 `RawDocument`로 돌려준다. 채널 매핑: NEWS→news, BLOG→blog, CAFE→community, WEB→출처 유형이 언론이면 news, 그 외는 매핑 미정(기본안은 §6 참조). 본문 없이 스니펫만 있는 문서는 메타데이터에 표시한다.
2. **문서 감성 분류.** 라벨(긍정·부정·중립·혼재·미분류)과 근거 구절·모델·프롬프트 버전을 문서 메타데이터에 Repository로 기록한다(2.0 Analytics가 이미 메타데이터 라벨을 세므로 집계 코드는 그대로 쓴다). Qwen이 라벨과 근거 구절을 내면 코드가 구절이 제목·본문·스니펫에 실제로 있는지 확인하고, 없으면 미분류로 둔다. 스니펫만 있는 문서는 스니펫 범위 안의 근거로만 분류한다.
3. **분류 검수.** 검토 화면에 이슈별 표본(기본 이슈당 최대 20건 또는 전체의 20% 중 큰 쪽, 상한 40건)을 보여 주고 동의·수정을 기록한다. 보고서 방법론에 "검수 N건 중 M건 일치(AI 분류 기준)"를 표기하며, 검수하지 않은 이슈는 "AI 분류, 미검수"로 표시한다.
4. **지표와 장 조립.** 7월 문서 §4.2의 지표 정의를 따른다. 긍정 비율은 중립 포함·제외를 모두 분모와 함께 표시, 미분류율 공개, 전월 차이는 %p, 전월 비교 자료가 없으면 산출 불가로 표시한다. 이슈 장은 새 엔진 IssueReport를 입력으로 쓰되 보고서의 모든 숫자는 2.0 값으로 교체한다. 새 엔진의 "언급량 및 추이" 문장은 월간 보고서에서 쓰지 않는다(숫자 출처 단일화).
5. **시각 자료와 HWPX 전체 조립.** 기존 VIS-02·07 외 필요한 VIS를 순서대로 추가하고 7월 12쪽 구성으로 조립한다. 한컴 실기 확인은 별도.

## 6. 결정한 것과 제가 정한 것

**사용자가 정함**: 7월 구성 유지 · 방식 B · Qwen 문서 분류 + 표본 검수.
**제가 정함(검토 요청)**
- 이슈 단위: 사용자 이슈명을 2.0 질의 문자열로 사용.
- 게시일 없는 글: 적재하지 않고 보류 건수만 표기.
- 일반 웹(WEB): 출처 유형이 언론이 아니면 월간 통계에서 제외하고 보류로 기록(채널 값 추가를 피하기 위함).
- 검수 표본 크기: 위 5.2-3의 기본값.
- 이슈 장 서술은 새 엔진 결과를 그대로 쓰고, 요약·시사점·방법론만 기존 Narrative(Gemini + 템플릿 폴백)가 만든다. 로컬 Qwen 어댑터 추가는 후속.
- Qwen은 로컬 qwen3:8b. 실행마다 결과가 달라질 수 있어, 분류 결과는 저장하고 보고서는 저장된 값만 사용한다.

## 7. 구현자에게 남긴 확인 사항

- (확인됨) 2.0 Analytics는 `CleanDocument.metadata["sentiment"]`가 `positive/negative/neutral/mixed`일 때만 센다(그 외는 `unclassified`). 문서 메타데이터는 기존 `DocumentRepository.upsert_clean`으로 쓸 수 있어 Repository 메서드와 스키마 추가 없이 분류 결과를 저장할 수 있다. 근거 구절·모델·프롬프트 버전·검수 상태는 같은 메타데이터의 별도 키에 둔다. `upsert_clean`이 기존 메타데이터를 덮어쓰지 않고 병합하는지는 구현 시 테스트로 확인한다.
- 재생 수집기가 워크플로 상태 머신(상태당 1회)과 충돌하지 않는지: 새 월 = 새 프로젝트, 이슈 전체를 한 번의 수집 실행으로 적재.
- 비교 기간: 전월 자료는 같은 방식으로 적재한 프로젝트가 있을 때만 연결한다.
- 새 모델·상태가 필요해 보이면 구현 전에 별도 승인을 받는다.

## 8. 검증 기준

- 적재 전후 문서 수가 일치한다(적재 + 보류 = 코퍼스 전체).
- 보고서 어디에도 Analytics 값이 아닌 건수·비율이 없다.
- 감성 분류의 모든 라벨에 확인된 근거 구절이 있고, 없는 것은 미분류다.
- 같은 승인본에서 HWPX·DOCX·Markdown이 나온다.
